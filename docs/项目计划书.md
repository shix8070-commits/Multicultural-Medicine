## 1. 项目目标

建成面向多民族公开健康证据的知识服务：文献可检索、可对照、可追溯；临床与科研共用同一文献库，走通「查证 → 论坛说现场 → 科研对照文献」的闭环。医生不在临床助手里上传观察。

系统回答「现在知道多少、值不值得研究」，不替代诊疗，不替代课题评审。

**本期验收目标：** 以「维吾尔族 × 华法林 × 出血风险」为题目，当着人能连续走通：临床助手对照 → 文献速查看出处 → 论坛发帖/看帖 → 科研助手做不做（只对照文献）→ 拒绝按帖子回答。两个 Agent 可答且诊疗类问题被拒答。

## 2. 范围

| 类别 | 内容 |
| --- | --- |
| 纳入 | 文献库（四类、速查、详情）；临床助手 Agent（对照现有研究，无上传观察）；科研助手 Agent（开题对照 / 做不做，只依据文献）；我的论坛（现场交流） |
| 不纳入 | 民族医学治法；病历系统；辅助诊断与处方；未发表数据；大众问答端；临床助手内脱敏观察上传 |
| Demo 边界 | 文献为预置示意数据。完整产品远环含「合法新文献回库后再查」，正式版实现 |

## 6. 质量与验收要点

不以「做了多少按钮」为完成标准，以同一题目能否当众走通为准：

1. 双端切换，共用文献库；四类浏览、导读、详情可用  
2. 临床：开始对话 → 结束 → 标红 → 上传  
3. 科研：现场发现可见上传次数与文献篇数；研判可写入记录  
4. Agent 可用；诊疗类问题拒答  
5. 信号不进入文献库  

未完成上传与研判，判定闭环未通过。

## 7. 风险与约束

| 风险 | 应对 |
| --- | --- |
| 文献样例不足或不可引用 | 先请导师圈选 3～8 条；Demo 可用示意结构，正式版必须换真出处 |
| 两端各做各的题目 | 全组锁定同一演示题，不换病、不换药 |
| 做成病历或辅助诊断 | 论坛发帖不得写病历；Agent 拒答怎么治、改药、剂量 |
| 只做检索、合不上环 | 验收强制：论坛发帖可见 + 科研助手只对照文献 + 拒按帖作答 |
| 人员未定导致并行冲突 | 分工确定前只推进文档与已有 Demo 联调，不新开互斥分支 |
